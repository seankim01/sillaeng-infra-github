# 05. EC2 On-Premise (IDC Openswan VPN) - AWS 콘솔 수동 배포 가이드

## 개요

이 문서는 AWS 콘솔을 통해 IDC VPC에 Openswan VPN 서버를 배포하고, Service VPC와 IPsec VPN 연결을 설정하는 초보자용 가이드입니다.

- **AWS 계정 Profile**: mzc-dsa04
- **리전**: ap-northeast-2 (서울)
- **VPC**: bundang-idc-bundang-vpc (192.168.0.0/16)
- **VPN 대상**: sillaeng-demo-service-vpc (172.25.0.0/22)

---

## Step 1. EC2 인스턴스 생성

### 1-1. Openswan VPN 서버 (Public)

EC2 > **Launch instances**

| 항목 | 설정값 |
|------|--------|
| Name | sillaeng-idc-bundang-ec2-public-bastion |
| AMI | Amazon Linux 2 (검색: "Amazon Linux 2 AMI" — **2023이 아닌 2 선택**) |
| Instance type | t3.medium |
| Key pair | mzc-dsa04-shared |
| Network > VPC | bundang-idc-bundang-vpc |
| Subnet | bundang-pub-01a |
| Auto-assign public IP | Enable |
| Security group | Select existing > `bundang-public-bastion-ec2` |
| Storage | 20 GiB, gp3 |
| Advanced > IAM instance profile | sillaeng-idc-mng-ssm-role (사전에 04번 가이드처럼 생성) |

**중요: Source/Destination Check 비활성화**
1. 인스턴스 생성 후 선택
2. **Actions** > **Networking** > **Change source/destination check**
3. **Stop** 체크 (비활성화) > **Save**

> 이 설정을 하지 않으면 VPN 트래픽이 전달되지 않습니다!

**Elastic IP 할당:**
1. EC2 > **Elastic IPs** > **Allocate Elastic IP address** > **Allocate**
2. EIP 선택 > **Actions** > **Associate** > Openswan 인스턴스 선택
3. 할당된 EIP를 메모 (Customer Gateway에 사용)

## Step 2. Openswan 설치 및 설정

Openswan EC2에 SSH 접속합니다:
```bash
ssh -i ~/.ssh/mzc-dsa04-shared.pem ec2-user@<Openswan_EIP>
```

### 2-1. Openswan 패키지 설치

```bash
sudo yum install -y openswan
```

### 2-2. IP Forwarding 활성화

```bash
sudo vi /etc/sysctl.conf
```

아래 내용을 파일 끝에 추가:
```
net.ipv4.ip_forward = 1
net.ipv4.conf.default.rp_filter = 0
net.ipv4.conf.default.accept_source_route = 0
net.ipv4.conf.all.rp_filter = 0
net.ipv4.conf.all.send_redirects = 0
net.ipv4.conf.default.send_redirects = 0
net.ipv4.conf.eth0.send_redirects = 0
net.ipv4.conf.default.accept_redirects = 0
net.ipv4.conf.all.accept_redirects = 0
```

적용:
```bash
sudo sysctl -p
```

### 2-3. VPN 터널 정보 확인

AWS 콘솔에서 VPN Connection 생성 후 (02.network 가이드의 Step 9 참조):
1. VPC > **Site-to-Site VPN connections** > 해당 VPN 선택
2. **Tunnel details** 탭에서 아래 정보 확인:
   - Tunnel 1 Outside IP address
   - Tunnel 2 Outside IP address
3. **Download configuration** 버튼 클릭 > Vendor: Generic 선택 > Download
4. 다운로드된 파일에서 **Pre-Shared Key** 확인

### 2-4. IPsec 설정 파일 생성

```bash
sudo vi /etc/ipsec.d/aws-vpn.conf
```

아래 내용 입력 (< > 부분을 실제 값으로 교체):
```
conn aws-vpn-tunnel1
    type=tunnel
    authby=secret
    left=<Openswan_Private_IP>
    leftid=<Openswan_EIP>
    leftnexthop=%defaultroute
    leftsubnet=192.168.0.0/16
    right=<AWS_Tunnel1_Outside_IP>
    rightsubnet=172.25.0.0/22
    pfs=yes
    auto=start
    ike=aes128-sha1;modp1024
    phase2alg=aes128-sha1;modp1024
    ikelifetime=28800s
    salifetime=3600s
    dpddelay=10
    dpdtimeout=30
    dpdaction=restart_by_peer
    overlapip=yes

conn aws-vpn-tunnel2
    type=tunnel
    authby=secret
    left=<Openswan_Private_IP>
    leftid=<Openswan_EIP>
    leftnexthop=%defaultroute
    leftsubnet=192.168.0.0/16
    right=<AWS_Tunnel2_Outside_IP>
    rightsubnet=172.25.0.0/22
    pfs=yes
    auto=start
    ike=aes128-sha1;modp1024
    phase2alg=aes128-sha1;modp1024
    ikelifetime=28800s
    salifetime=3600s
    dpddelay=10
    dpdtimeout=30
    dpdaction=restart_by_peer
    overlapip=yes
```

**각 항목 설명:**
- `left`: Openswan EC2의 **Private IP** (예: 192.168.0.19)
- `leftid`: Openswan EC2의 **EIP** (예: 3.34.225.161)
- `leftsubnet`: IDC 네트워크 대역
- `right`: AWS VPN 터널의 Outside IP (콘솔에서 확인)
- `rightsubnet`: Service VPC 대역

Private IP 확인 방법:
```bash
hostname -I | awk '{print $1}'
```

### 2-5. Pre-Shared Key 설정

```bash
sudo vi /etc/ipsec.d/aws-vpn.secrets
```

```
<Openswan_EIP> <Tunnel1_Outside_IP> : PSK "<Tunnel1_PSK>"
<Openswan_EIP> <Tunnel2_Outside_IP> : PSK "<Tunnel2_PSK>"
```

### 2-6. ipsec.conf 메인 설정

```bash
sudo vi /etc/ipsec.conf
```

전체 내용을 아래로 교체:
```
config setup
    protostack=netkey
    nat_traversal=yes
    virtual_private=%v4:10.0.0.0/8,%v4:192.168.0.0/16,%v4:172.16.0.0/12
    oe=off

include /etc/ipsec.d/*.conf
```

### 2-7. iptables FORWARD 규칙 추가

```bash
sudo iptables -I FORWARD 1 -s 192.168.0.0/16 -d 172.25.0.0/22 -j ACCEPT
sudo iptables -I FORWARD 2 -s 172.25.0.0/22 -d 192.168.0.0/16 -j ACCEPT
sudo service iptables save
```

### 2-8. IPsec 서비스 시작

```bash
sudo systemctl enable ipsec
sudo systemctl restart ipsec
```

### 2-9. VPN 상태 확인

```bash
# IPsec 상태 확인
sudo ipsec status

# 터널 연결 확인
sudo ipsec whack --status | grep "established"

# AWS 콘솔에서도 확인
# VPC > Site-to-Site VPN connections > Tunnel details > Status: UP
```

## Step 3. Route Table에 VPN 경로 추가

VPN 터널이 UP된 후, IDC Private 서브넷에서 Service VPC로의 경로를 추가합니다.

1. VPC > **Route tables** > `sillaeng-idc-rt-bundang-private` 선택
2. **Routes** 탭 > **Edit routes** > **Add route**
   - Destination: `172.25.0.0/22`
   - Target: **Network Interface** > Openswan EC2의 ENI 선택
3. **Save changes**

## 문제 해결 (Troubleshooting)

| 증상 | 원인 | 해결 |
|------|------|------|
| 터널 DOWN | Openswan 설정 오류 또는 PSK 불일치 | /var/log/pluto.log 확인 |
| 터널 UP인데 통신 안됨 | iptables FORWARD 차단 | iptables -L FORWARD로 확인 |
| 터널 UP인데 통신 안됨 | Source/Dest Check 미비활성화 | EC2 설정에서 비활성화 |
| 터널 UP인데 통신 안됨 | Route Table에 경로 없음 | 172.25.0.0/22 경로 추가 |
| Connection refused | 대상 서버에 웹서비스 미설치 | apache2/httpd 설치 확인 |

```bash
# 로그 확인
sudo tail -f /var/log/pluto.log

# IPsec 재시작
sudo systemctl restart ipsec

# 설정 검증
sudo ipsec verify
```
