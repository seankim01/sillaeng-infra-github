# 06. Application Load Balancer (ALB) - AWS 콘솔 수동 배포 가이드

## 개요

이 문서는 AWS 콘솔을 통해 ALB를 생성하고 개발 서버(service-ec2-dev-01a)에 연결하는 초보자용 가이드입니다.

- **AWS 계정 Profile**: mzc-dsa04
- **리전**: ap-northeast-2 (서울)
- **VPC**: sillaeng-demo-service-vpc (172.25.0.0/22)
- **대상 EC2**: service-ec2-dev-01a (개발 서버)

---

## 사전 조건

- 02.network 가이드의 모든 리소스가 생성된 상태
- 04.ec2 가이드의 개발 서버(service-ec2-dev-01a)가 생성된 상태
- 개발 서버에서 웹서버(Apache)가 80 포트에서 실행 중인 상태

---

## Step 1. Target Group 생성

Target Group은 ALB가 트래픽을 전달할 대상을 정의합니다.

1. AWS 콘솔 > 검색창에 **EC2** 입력 > EC2 서비스 클릭
2. 왼쪽 메뉴 하단 **Load Balancing** > **Target Groups** 클릭
3. **Create target group** 클릭
4. 아래와 같이 설정:

### Basic configuration

| 항목 | 설정값 |
|------|--------|
| Target type | Instances |
| Target group name | sillaeng-demo-tg-dev |
| Protocol : Port | HTTP : 80 |
| IP address type | IPv4 |
| VPC | sillaeng-demo-service-vpc |
| Protocol version | HTTP1 |

### Health checks

| 항목 | 설정값 |
|------|--------|
| Health check protocol | HTTP |
| Health check path | / |
| Advanced > Port | Traffic port |
| Healthy threshold | 3 |
| Unhealthy threshold | 3 |
| Timeout | 10 seconds |
| Interval | 30 seconds |
| Success codes | 200-399 |

5. **Next** 클릭

### Register targets

1. Available instances 목록에서 `sillaeng-demo-service-ec2-dev` 인스턴스 체크 ✅
2. **Ports for the selected instances**: `80` 확인
3. **Include as pending below** 클릭
4. 하단에 인스턴스가 추가된 것 확인
5. **Create target group** 클릭

---

## Step 2. ALB 생성

1. 왼쪽 메뉴 **Load Balancing** > **Load Balancers** 클릭
2. **Create load balancer** 클릭
3. **Application Load Balancer** 선택 > **Create**

### Basic configuration

| 항목 | 설정값 |
|------|--------|
| Load balancer name | sillaeng-demo-service-alb-ext |
| Scheme | Internet-facing |
| IP address type | IPv4 |

### Network mapping

| 항목 | 설정값 |
|------|--------|
| VPC | sillaeng-demo-service-vpc |
| Mappings | ap-northeast-2a 체크 > `service-pub-01a` 선택 |
|  | ap-northeast-2c 체크 > `service-pub-02c` 선택 |

> 최소 2개 AZ를 선택해야 합니다.

### Security groups

1. 기본 SG 제거 (X 버튼)
2. `service-pub-alb` 선택

### Listeners and routing

| 항목 | 설정값 |
|------|--------|
| Protocol | HTTP |
| Port | 80 |
| Default action | Forward to > `sillaeng-demo-tg-dev` 선택 |

4. 하단 **Create load balancer** 클릭

---

## Step 3. 생성 확인

1. Load Balancers 목록에서 `sillaeng-demo-service-alb-ext` 상태가 **Active**가 될 때까지 대기 (2~3분)
2. **DNS name** 복사 (예: `sillaeng-demo-service-alb-ext-123456789.ap-northeast-2.elb.amazonaws.com`)

## Step 4. 동작 테스트

브라우저 또는 터미널에서 ALB DNS로 접속:

```bash
curl http://<ALB_DNS_Name>
```

정상이면 개발 서버의 Apache 페이지가 표시됩니다:
```html
<h2>Server Information</h2>
<p>Hostname: ip-172-25-2-xx</p>
<p>IP: 172.25.2.xx</p>
```

## Step 5. (선택) HTTPS 설정

HTTPS를 사용하려면 ACM 인증서가 필요합니다.

### 5-1. ACM 인증서 발급

1. 검색창에 **Certificate Manager** 입력 > ACM 서비스 클릭
2. **Request a certificate** > **Request a public certificate** > **Next**
3. Domain name: `your-domain.com` 입력
4. Validation method: DNS validation 선택
5. **Request** > DNS 검증 레코드를 도메인의 DNS에 추가
6. 검증 완료 후 Status: **Issued**

### 5-2. HTTPS Listener 추가

1. Load Balancers > ALB 선택 > **Listeners** 탭
2. **Add listener**
3. 설정:
   - Protocol: HTTPS
   - Port: 443
   - Default action: Forward to > `sillaeng-demo-tg-dev`
   - Default SSL/TLS certificate: ACM에서 발급받은 인증서 선택
4. **Add**

### 5-3. HTTP → HTTPS 리다이렉트 (선택)

1. HTTP:80 리스너 선택 > **Edit**
2. Default action을 **Redirect to** 로 변경:
   - Protocol: HTTPS
   - Port: 443
   - Status code: 301
3. **Save changes**

## ALB 구성 요약

```
인터넷 → ALB (HTTP:80) → Target Group (tg-dev) → EC2 (개발 서버, port 80)
```

| 구성요소 | 이름 | 설명 |
|---------|------|------|
| ALB | sillaeng-demo-service-alb-ext | Internet-facing, HTTP:80 |
| Target Group | sillaeng-demo-tg-dev | HTTP:80, instance target |
| Target | service-ec2-dev-01a | 개발 서버 (Apache) |
| Security Group | service-pub-alb | 80, 443 허용 |

---

## 문제 해결

| 증상 | 원인 | 해결 |
|------|------|------|
| ALB가 Provisioning에서 멈춤 | 서브넷 설정 오류 | 2개 이상 AZ의 Public Subnet이 연결되었는지 확인 |
| Target이 unhealthy | EC2에서 웹서버 미실행 | EC2 접속 후 `systemctl status apache2` 확인 |
| Target이 unhealthy | SG에서 ALB→EC2 통신 차단 | EC2 SG에 VPC CIDR(172.25.0.0/22) 80포트 허용 확인 |
| 504 Gateway Timeout | EC2 응답 없음 | EC2 상태 확인, 서비스 재시작 |
| 접속 안됨 | ALB SG에 80/443 미허용 | `service-pub-alb` SG 규칙 확인 |
