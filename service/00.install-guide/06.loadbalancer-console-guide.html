Step 1. Target Group 생성

경로: EC2 > Load Balancing > Target Groups > Create target group

1-1. Basic configuration

항목설정값
Target typeInstances
Target group namesillaeng-demo-tg-dev
Protocol : PortHTTP : 80
IP address typeIPv4
VPCsillaeng-demo-service-vpc
Protocol versionHTTP1

1-2. Health checks

항목설정값설명
Health check protocolHTTP대상 프로토콜
Health check path/체크할 URL 경로
PortTraffic port타겟과 동일 포트
Healthy threshold3연속 성공 횟수
Unhealthy threshold3연속 실패 횟수
Timeout10 seconds응답 대기 시간
Interval30 seconds체크 주기
Success codes200-399정상 응답 코드

1-3. Register targets

  1. Available instances에서 sillaeng-demo-service-ec2-dev 체크
  2. Port: 80 확인
  3. Include as pending below 클릭
  4. Create target group 클릭
graph LR
    TG["Target Group
sillaeng-demo-tg-dev"] --> EC2["EC2: service-ec2-dev-01a
Port: 80
Health: Healthy ✅"]

Step 2. ALB 생성

경로: EC2 > Load Balancing > Load Balancers > Create > Application Load Balancer

2-1. Basic configuration

항목설정값
Load balancer namesillaeng-demo-service-alb-ext
SchemeInternet-facing
IP address typeIPv4

2-2. Network mapping

항목설정값
VPCsillaeng-demo-service-vpc
ap-northeast-2aservice-pub-01a ✅
ap-northeast-2cservice-pub-02c ✅
최소 2개 AZ를 선택해야 합니다. Public Subnet을 선택합니다.

2-3. Security groups

기본 SG 제거 후 service-pub-alb 선택 (HTTP 80, HTTPS 443 허용)

2-4. Listeners and routing

ProtocolPortDefault action
HTTP80Forward to → sillaeng-demo-tg-dev

Create load balancer 클릭

Step 3. 동작 확인

  1. Load Balancers에서 상태가 Active가 될 때까지 대기 (2~3분)
  2. DNS name 복사
  3. 브라우저에서 접속 테스트
# 터미널에서 테스트
curl http://<ALB_DNS_Name>

Troubleshooting

증상원인해결
ALB Provisioning 멈춤서브넷 설정 오류2개 AZ Public Subnet 확인
Target: unhealthy웹서버 미실행EC2에서 systemctl status apache2
Target: unhealthySG 차단EC2 SG에 VPC CIDR:80 허용 확인
504 TimeoutEC2 응답 없음EC2 상태 및 서비스 확인
접속 불가ALB SG 미설정service-pub-alb SG에 80/443 확인
