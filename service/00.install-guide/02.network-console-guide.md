# 02. Service Network - AWS 콘솔 수동 배포 가이드

## 개요

이 문서는 AWS 콘솔을 통해 Service VPC 네트워크를 수동으로 생성하는 초보자용 가이드입니다.

- **AWS 계정 Profile**: mzc-dsa04
- **리전**: ap-northeast-2 (서울)
- **VPC 이름**: sillaeng-demo-service-vpc
- **CIDR**: 172.25.0.0/22

---

## Step 1. VPC 생성

1. AWS 콘솔 로그인 후 상단 검색창에 **VPC** 입력 > VPC 서비스 클릭
2. 왼쪽 메뉴에서 **Your VPCs** 클릭
3. 우측 상단 **Create VPC** 버튼 클릭
4. 아래와 같이 입력:

| 항목 | 입력값 |
|------|--------|
| Resources to create | VPC only |
| Name tag | sillaeng-demo-service-vpc |
| IPv4 CIDR | 172.25.0.0/22 |
| IPv6 CIDR block | No IPv6 CIDR block |
| Tenancy | Default |

5. **Create VPC** 클릭

---

## Step 2. DNS 설정 활성화

1. 생성된 VPC 선택 > **Actions** > **Edit VPC settings**
2. 아래 두 항목 체크:
   - Enable DNS resolution ✅
   - Enable DNS hostnames ✅
3. **Save** 클릭

---

## Step 3. Internet Gateway 생성 및 연결

1. 왼쪽 메뉴 **Internet gateways** 클릭
2. **Create internet gateway** 클릭
3. Name tag: `sillaeng-demo-service-igw` 입력 후 **Create**
4. 생성된 IGW 선택 > **Actions** > **Attach to VPC**
5. `sillaeng-demo-service-vpc` 선택 후 **Attach**

---

### Public Subnet에 자동 퍼블릭 IP 할당 설정

1. `service-pub-01a` 선택 > **Actions** > **Edit subnet settings**
2. **Enable auto-assign public IPv4 address** 체크 > **Save**
3. `service-pub-02c`에도 동일하게 설정

---

## Step 5. NAT Gateway 생성 (Regional 모드)

1. 왼쪽 메뉴 **NAT gateways** 클릭
2. **Create NAT gateway** 클릭
3. 아래와 같이 입력:

| 항목 | 입력값 |
|------|--------|
| Name | sillaeng-demo-service-nat-regional |
| Subnet | service-pub-01a |
| Connectivity type | Public |

4. **Elastic IP allocation ID** 항목에서 **Allocate Elastic IP** 클릭 (자동 할당)
5. **Create NAT gateway** 클릭

> 참고: Regional NAT Gateway는 단일 NAT로 모든 AZ를 커버하여 비용을 절감합니다.

---

## Step 6. Route Table 생성

### 6-1. Public Route Table

1. 왼쪽 메뉴 **Route tables** > **Create route table**
2. Name: `sillaeng-demo-rt-service-public` / VPC: `sillaeng-demo-service-vpc`
3. 생성 후 해당 RT 선택 > **Routes** 탭 > **Edit routes**
4. **Add route** 클릭:
   - Destination: `0.0.0.0/0`
   - Target: **Internet Gateway** > `sillaeng-demo-service-igw`
5. **Save changes**
6. **Subnet associations** 탭 > **Edit subnet associations**
7. `service-pub-01a`, `service-pub-02c` 체크 > **Save associations**

### 6-2. Private Route Tables

아래 Route Table을 각각 생성합니다. 모든 Private RT에 동일한 NAT 경로를 추가합니다.

| Route Table 이름 | 연결할 서브넷 |
|-----------------|-------------|
| sillaeng-demo-rt-service-private-app | service-pri-app-01a, service-pri-app-02c |
| sillaeng-demo-rt-service-private-gpu-infer | service-pri-gpu-infer-01a, service-pri-gpu-infer-02c |
| sillaeng-demo-rt-service-private-gpu-train | service-pri-gpu-train-01a, service-pri-gpu-train-02c |
| sillaeng-demo-rt-service-private-dev | service-pri-dev-01a, service-pri-dev-02c |
| sillaeng-demo-rt-service-private-db | service-pri-db-01a, service-pri-db-02c |
| sillaeng-demo-rt-service-private-devdb | service-pri-devdb-01a, service-pri-devdb-02c |

각 Route Table 생성 후:
1. **Routes** 탭 > **Edit routes** > **Add route**
   - Destination: `0.0.0.0/0`
   - Target: **NAT Gateway** > `sillaeng-demo-service-nat-regional`
2. **Save changes**
3. **Subnet associations** 탭에서 해당 서브넷 연결

---

## Step 8. VPC Endpoint 생성

### 8-1. S3 Gateway Endpoint

1. 왼쪽 메뉴 **Endpoints** > **Create endpoint**
2. 설정:
   - Name: `ep-s3-service`
   - Service category: AWS services
   - Services: 검색창에 `s3` 입력 > `com.amazonaws.ap-northeast-2.s3` (Type: Gateway) 선택
   - VPC: `sillaeng-demo-service-vpc`
   - Route tables: public, private-app, private-gpu-infer, private-gpu-train, private-dev 선택
3. **Create endpoint**

### 8-2. SSM Interface Endpoints (3개)

아래 3개를 동일한 설정으로 생성합니다:

| Name | Service |
|------|---------|
| ep-ssm-service | com.amazonaws.ap-northeast-2.ssm |
| ep-ssmmessages-service | com.amazonaws.ap-northeast-2.ssmmessages |
| ep-ec2messages-service | com.amazonaws.ap-northeast-2.ec2messages |

각 Endpoint 설정:
1. Service category: AWS services
2. Service: 위 표 참조
3. VPC: `sillaeng-demo-service-vpc`
4. Subnets: `service-pri-app-01a`, `service-pri-app-02c` 선택
5. Security groups: `service-private-endpoint` 선택
6. **Enable DNS name** 체크 ✅
7. **Create endpoint**

---

## Step 9. VPN Gateway 설정 (IDC 연결)

### 9-1. Virtual Private Gateway (VGW) 생성

1. 왼쪽 메뉴 **Virtual private gateways** > **Create virtual private gateway**
2. Name: `sillaeng-demo-service-vgw`
3. ASN: Amazon default ASN
4. **Create** > 생성 후 **Actions** > **Attach to VPC** > `sillaeng-demo-service-vpc`

### 9-2. Customer Gateway (CGW) 생성

1. 왼쪽 메뉴 **Customer gateways** > **Create customer gateway**
2. 설정:
   - Name: `sillaeng-demo-sillaeng-cgw-idc`
   - BGP ASN: `65001`
   - IP Address: `3.34.225.161` (Openswan EC2의 EIP)

### 9-3. VPN Connection 생성

1. 왼쪽 메뉴 **Site-to-Site VPN connections** > **Create VPN connection**
2. 설정:
   - Name: `sillaeng-demo-sillaeng-idc-vpn`
   - Target gateway type: Virtual Private Gateway > `sillaeng-demo-service-vgw`
   - Customer gateway: Existing > `sillaeng-demo-sillaeng-cgw-idc`
   - Routing options: **Static**
3. **Create VPN connection**
4. 생성 후 **Static routes** 탭 > **Edit static routes** > `192.168.0.0/16` 추가

### 9-4. Route Propagation 설정

각 Private Route Table에서:
1. Route Table 선택 > **Route propagation** 탭 > **Edit route propagation**
2. `sillaeng-demo-service-vgw` 체크 ✅ > **Save**

적용 대상: service-private-app, service-private-gpu-infer, service-private-gpu-train, service-private-dev, service-private-db, service-private-devdb

---

## 완료 확인

- VPC, Subnet, IGW, NAT Gateway가 모두 Available 상태인지 확인
- Route Table의 Routes에 경로가 정상 등록되었는지 확인
- VPN Connection의 Tunnel이 UP 상태인지 확인 (Openswan 설정 후)
